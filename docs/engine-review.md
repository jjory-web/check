15개 XLS의 모든 데이터 행을 변환했다. 원본 표제어·구성 단위·품사·활용형을 색인에 남겼다.
형태소 분석과 연결하는 현대 한글 단어 Map은 동음이의어 통합 및 제한 항목 제외 후 283,354개다.
따라서 **436,587개의 모든 항목을 무조건 붙여쓰기 대상으로 삼는다는 뜻은 아니다.**

`살펴-보다`의 하이픈과 `암모늄^명반`의 지붕표는 의미가 다르다. 전자는 내부 경계 제거, 후자는 공백 보존으로 처리한다.
`보다(01)` 같은 번호를 제거하되 같은 표제어의 품사는 합친다. 북한어·옛말·방언·비표준어 등의 제한 표지가 있는 행은 교정 목표로 쓰지 않는다.
제한 판정은 현재 행 단위이므로 여러 뜻 중 일부만 제한된 항목도 보수적으로 제외될 수 있다.
색인 크기는 약 18.5 MB이며 브라우저 최초 접속에서는 데이터 다운로드·색인 생성 시간이 든다.
뜻풀이 전체를 이용한 의미 판별 모델을 구축한 것은 아니다.

## 3. 공통 검사 절차

1. 문단별 Garu 분석 및 위치 변환. 긴 문단은 1,500자 근처의 공백에서 나눠 분석한다.
2. 인접 2~4어절을 결합한 후보 생성. 줄바꿈·문장 부호·영문 식별자 경계를 넘지 않는다.
3. 전체 단어 색인, 원본 활용 정보, 어간+어미 분석을 이용해 후보 표제어를 찾는다.
4. 관형어·대명사·수량 표현·앞말 조사 등을 검사해 정상적인 별개 단어 구성을 보호한다.
5. 보조 용언·관형어 뒤 명사·의존 명사·분리된 조사는 품사와 분리/결합 전후 분석이 맞을 때만 제안한다.
6. 같은 원고의 정확한 범위만 밑줄로 표시한다. 사용자가 ‘수정 적용’을 누르기 전에는 원고를 바꾸지 않는다.

Garu 형태소의 `start/end`는 어절 단위 범위이며 각 형태소의 실제 글자 위치가 아니다.
따라서 보조 용언 분리 위치를 토큰의 `start`로 그대로 결정하지 않고 양쪽 문자열의 재분석을 비교한다.
또 Garu가 `다먹었다`를 `따먹다` 활용처럼 분석한 실측 사례가 있어, 바뀌지 않아야 하는 어간 앞부분과 원문도 비교한다.
이 검사는 완전한 한국어 활용 생성기가 아니며 불확실한 활용형의 미검출이 남는다.

보조 용언의 원칙 표기 권장도 허용되는 붙여쓰기를 무조건 틀린 표기라고 단정하지 않는다.

## 5. 자동 검증

- 엔진 테스트: **82/82 통과**, 실제 Garu WASM 및 전체 사전 사용
- 브라우저 통합 테스트: **7/7 통과**, 실제 Chromium 143, Playwright 1.58.2
- Vite production build 성공
- `git diff --check` 통과
- 실패/skip/todo: 0

브라우저 테스트는 `/check/` 하위 경로에서 실행했다. 다음을 확인한다.

- 사전·Worker·WASM·모델 로드, 원고의 빨간 물결 밑줄 및 수정 적용
- 빠른 입력 변경 시 이전 결과 폐기, 반복 표현 중 한 항목만 무시
- 시리즈 규칙만 노출, 추가·저장·새로고침 후 유지 및 적용
- 글자 수·원고지 매수·목표 분량 및 XLSX 다운로드
- 사전 503, WASM 503, Worker 스크립트 로드 실패 시 완료/정상으로 오표시하지 않음
- 엔진 미연결 시 시리즈 규칙 독립 동작

빌드 후 `npm run test:browser`를 실행한다. `npm run test:all`은 엔진 테스트·빌드·브라우저 테스트를 순서대로 실행한다.
변경한 배포 workflow에도 같은 검증을 추가했지만 **원격 GitHub Actions 실행은 아직 확인하지 않았다.**
원문 로그는 `validation.txt`에 있다. 이 테스트 통과율은 일반 원고 교정 정확도나 재현율이 아니다.

## 6. 성능 실측

반복 문단 `학생이 글을 읽었다. 엉망 진창인 방을 살펴 보았다.`를 사용한 로컬 Node 측정:

| 입력 | 초기 전체 텍스트 분석 | 문단 분석·캐시 적용 후 |
| --- | ---: | ---: |
| 3,000자, 검토 200건 | 약 430 ms | 약 23 ms |
| 15,000자, 검토 1,000건 | 약 8,890 ms | 약 29 ms |

반복 문단으로 캐시 적중률이 높다. 일반 원고·저사양 장치·최초 로딩의 속도를 보장하는 수치가 아니다.
긴 단일 문단은 공백에서 나누므로 그 경계에서는 문맥 정보가 줄어들 수 있다.

## 7. 남은 한계와 다음 작업

- 사전 전체를 색인화했어도 모든 표제어·모든 활용형을 탐지한다는 뜻은 아니다. 분석기 오분석, 보호 조건, 최대 4어절/결합 후보 64자 제한 때문에 미검출이 있다.
- 동음이의어의 뜻풀이·문형을 문장 의미와 매칭하지 않는다. 사전 결합 제안은 정확한 오류 판정이 아니라 검토 후보다.
- 보수적인 대명사 보호로 `우리 나라`를 제안하지 않는 사례, Garu 품사 판정 때문에 `좋아보인다`를 분리하지 않는 사례가 확인됐다.
- 원래 `컨텐츠→콘텐츠`, `몇일→며칠` 등 개별 문자열 목록은 제거했다. 이를 대체할 외래어 표기 용례·비표준어 관계 데이터 기반의 범용 철자 교정은 **아직 구현하지 않았다.**
- 구·전문어의 원칙/허용 표기, 접사, 고유명사, 모든 숫자·단위 표기를 포괄하지 않는다.
- 제47항의 모든 허용·불허 조건을 판정하지 않는다. 보조 용언을 분리하는 원칙 권장을 제공한다.
- Safari·Firefox·휴대전화 실기기와 운영 Pages 배포본은 이번 실행에서 검증하지 않았다.
- 다음 정확도 개선은 집필 원고의 정답 코퍼스를 별도로 만들고 오검출/미검출을 분리 측정한 뒤, 뜻풀이·문형·용례를 활용한 후보 판별을 추가하는 것이 우선이다.
